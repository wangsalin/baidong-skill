# 白洞 · 科幻情景喜剧卡通

写分镜、设计道具、画角色、制作封面和检查成片时使用。账号配色见 `account.md`，角色造型和参数见 `characters.md`，封面三种风格与横竖实图见 `covers.md`，执行命令见 `production.md`。

风格依据：Lemo-Opuscar 的 [scifi-toon / STYLE.md](https://github.com/lemomo-ai/lemo-opuscar/blob/main/styles/scifi-toon/STYLE.md) 和 [DIRECTOR.md](https://github.com/lemomo-ai/lemo-opuscar/blob/main/DIRECTOR.md)。学习画法、表演和镜头语言，使用白洞自己的角色、道具与故事。保留用户确认的黑白灰主角、蓝围巾、中文字体和选定 BGM；这些是白洞对原风格的品牌适配。

## 1. 生活问题怎样变成科幻情景

人物先有一个具体的生活目标，科幻手段把其中的矛盾或机制变得可见、可操作。它可以是一件外壳破旧的装置、一次选择模拟、同一处境的两种结果；根据题目选择，不把每期固定成传送门或平行宇宙旅行。

写进本期 `TREATMENT.md`：人物要完成什么、科幻表达展示哪个关系、角色如何操作、出现什么结果、结果怎样改变判断。能用一个装置讲清时，不再添加设定。装置出现后仍需直接用口语说明概念和因果。

虚构装置、模拟结果和情景数字标为情景演绎或假设对比。真实数据的调取画面显示实际来源、时间、单位和统计口径；技术外观不能把假设包装成已查到的事实。

## 2. 画法与色彩

- 粗深色轮廓、平涂、硬边阴影、大眼白和小瞳孔。避免柔光渐变、塑料立体感和光滑图标式人物。
- 沿用 `toon.js` 的屏幕空间描边：人物和主要道具约 7 px，背景细节约 4–6 px。推近镜头时线宽保持稳定；线稿按 12 fps 在三组轻微扰动间切换，背景可降低抖动幅度以保证阅读。
- 人物姿态、口型和眨眼按 12 fps 换形；摄像机、飞行道具和转场按成片的 24 fps 连续变化。
- 每个主要场景选三至五种主色，区分主色、对比色和强调色。高饱和色用在关键道具和视觉重点，背景保留明暗层次；连续发生的动作保持配色连续，不因换一句台词就换世界。
- A1–D2 保持各自注册表中的黑白灰主体、体块和识别配饰。场景、图表、道具和临时人物可用彩色；A1 的蓝色长围巾不限制全画面的蓝色使用。优先调整背景位置和明暗，保持每位人物的配饰、轮廓和字幕清楚。
- 科幻装置的发光用少量平面半透明色环，主次明确；普通物件和字幕不统一套霓虹光。场景应能辨认地点、前后关系和人物正在处理的物件。

## 3. 表演先于口型

分镜写角色正在做的动作和情绪变化，例如“攥紧票据 → 看向出口 → 躲开对方视线 → 松手”。呼吸、眨眼和嘴动只能补充表演。

- 关键动作有预备、动作和收势。用现有 `armF / armB`、`lean`、`headTilt`、`expr / E` 等参数插值；不能靠人物整张平移代替走路或伸手。
- 视线对准对方、物件或读数，眉毛、嘴型和身体姿态配合。谁受到冲击，就给谁的反应；老白也可以嘴硬、心虚或被问住，小问也可以平静地指出问题。
- 手持物件跟随手的位置，并处理手掌与物件的遮挡。若本期需要模板没有的动作，在本期镜头中补姿态并检查，不编造不存在的预设名。
- 摘掉字幕看关键帧，仍应能看出人物是在阻拦、犹豫、发现还是放弃。角色剪影和各自配饰保持可辨识；不要把不同人物画成同一套体块、围巾或表情。

## 4. 镜头跟随信息和反应

| 需要让观众看懂什么 | 优先考虑的镜头 |
|---|---|
| 两人各要做什么、谁拦着谁 | 带环境和动作的双人中景或全景 |
| 钱、票据、按钮或数据发生了什么 | 物件插入特写，给足读清关键内容的时间 |
| 一句反驳为何让人接不上话 | 切受影响人物的反应近景 |
| 人物正在核对哪项信息 | 越肩看屏幕或读数，再接人物反应 |
| 两个选择的差异 | 保持相同构图做对照，只改变与机制有关的部分 |
| 人物最后怎样选择 | 回到能够看见动作结果的镜头 |

镜头变化应有原因；争执可用硬切和短促摇移，被问住可停在近景。跨地点或模拟切换可用白洞圆环转场，同一场景普通对话可直接硬切。不要用固定双人站姿加说明牌承包整期解释，也不要只靠整体放大冒充反应镜头。说明牌适合保留必要关键词或对比，不替代人物行动。

### 生活场景与机制画面的衔接

先在本期分镜写清楚：上一镜留下什么疑问，下一镜让观众看见什么新信息，用哪个物件、方向或动作承接。转场跟随地点、观察尺度和人物判断的变化，不按固定秒数插特效。

- **情景 → 细节**：沿人物视线或手指硬切到物件、痕迹或俯视示意；保留可辨认的参照物，让观众知道正在看哪里。真实资料、假设示意和虚构情景分别标清，不把示意冒充实测。
- **情景 → 机制**：保持同一物体的形状、颜色或位置关系，从局部进入机制示意；解释依次展示原因、过程和结果，连续动作不因换一句台词从头播放。
- **跨地点、进入模拟**：可用人物操作装置、镜头推入和白洞圆环衔接。新旧场景在遮罩覆盖时切换，圆环展开后直接呈现新场景；动作和音效使用同一个时间点，转场期间清掉上一句字幕。
- **对照与回扣**：比较不同机制时保持构图与参照物一致，只改变要解释的条件；结尾回到开头的物件或现场，让观众用新理解回答最初的问题。
- **反应与主讲**：发现线索后给必要的视线、停顿和反应。谁说话谁出镜；证据占主要画面时，正在说话的角色可在边侧同框，并保持实际口型，不能用其他角色或空镜承接他的声音。

保留白洞既定的角色、色彩逻辑、字体和字幕安全区。原版的动作承接、反应近景与构图对照可借鉴；具体镜头、时长与视觉方案服务于本期生活问题，不照搬原 demo 的时间线。

验收转场要查看切点前后的连续帧，确认遮罩实际覆盖画面、新场景及时出现、没有回露旧画面；竖屏要检查四角，不能只凭横版效果或低频总览图判断。

### 真实资料与 B-roll

B-roll 是辅助讲解的资料镜头。数据类选题应主动寻找真实图片、视频和报告原页，优先使用与本句解释有关、来源可追溯且使用条件允许的资料，不设每期固定数量或占比。

- **查清画面是什么**：核对来源、作者/机构、拍摄或发布日期、地点和事件；无法确认的项目标为未确认。真实门店空镜只能说明所见场景，不能证明倒闭率或某家店亏损；非本事件素材标为场景参考，AI生成或摆拍标为情景演绎，不冒充实拍证据。
- **查清能怎样使用**：优先用户自有、已授权或许可条件明确的素材；公开可看不等于可直接复用。记录适用的使用依据和署名要求，不能确认时保留为候选，不进入正式成片，不去水印伪装自有。无可用素材时可用可复核的自制图表，不把生成图片当真实资料替代。
- **与台词和证据对应**：在本期分镜或 `TREATMENT.md` 记录素材对应的台词/事实ID、用途、拟用片段和标注。报告原页放大关键行时保留足以识别来源、期间、单位和脚注的上下文；裁切、加速或重排不能改变原意。
- **继承白洞画面与出镜规则**：真实素材可作为资料窗、越肩屏幕、对照镜头或带人物画中画的画面，沿用本期色彩、字体、字幕安全区和既有模板。有人物台词时，实际说话角色继续可见并按本人音轨驱动口型，通过 `check-cast.mjs`；不以头像、姓名字幕或他人代替。全屏资料空镜可放在无人物台词的间隙。
- **本地固定并留出处**：进入制作的素材保存为本期本地文件，视频片段记录原片时间范围；在已有 `CREDITS` 中记录文件名、原始链接、作者/机构、日期、使用依据、必要标注及使用位置。候选、已核实可用、已入片要区分，找到链接不等于已取得或已使用素材。
- **四版各自验收**：横竖版分别检查裁切后是否失去上下文、来源与字表是否可读、素材原声是否干扰固定角色配音；英文版保留原资料身份并适配译注。真实资料、统计图、假设示意和人物演绎在画面中清楚区分。

## 5. 节奏和声音

对白保持紧凑，关键定义和因果链说完整，不让抢话盖住解释。角色要看、试、犹豫或反应时允许留白，不设置统一的半秒上限。短反应可先试约 0.3–1.2 秒，更长停顿须有可读的表演或转折；最终以带声播放的观感决定，不能用停顿凑时长。

在 `BEATS` 中用已有的 `pause`、`mark` 和反应镜头表达这些时刻。字幕及时退场，不让旧台词长期挂在反应画面。需要停顿时配合调低或短暂切掉音乐，保留房间、设备或物件的声音；不必每个笑点都静音。

配乐继续优先按用户音乐库选择，正常段落应能清楚听见。关键动作配对应材质的声音，例如纸票、按钮、座椅或装置启动。综合响度不能代替对白清晰度检查；定稿时用成片回听或听写复核。

## 6. 解释画面的验收

观众应能说出：这个名词指什么、什么条件下适用、为什么出现眼前的结果、人物接下来应比较什么。角色直接说出必要定义和因果，画面负责让这条关系可见。

例如沉没成本的假设比较：两条路径都显示同一笔已花且无法收回的票钱，再展示剩余时间的不同用途。共同成本保持一致，新增投入另行显示；把“沉没成本本身”与“因舍不得它而继续投入”分别讲清。这个例子用于检查表达，不是每期剧情模板。

进入实际制作后，用本期真实绘制代码检查至少两张代表性样帧：一张体现人物冲突或反应，一张讲清机制。已有角色转面图可复用；关键动作按约 0.2 秒间隔检查连续帧。整片带声音看一遍，检查姿态、视线、持物、字幕遮挡、色彩层次、停顿和原理是否一致。只完成规则修订时，如实报告文档验证，不声称成片效果已验证。
