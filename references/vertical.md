# 白洞竖屏版式与制作

每期默认制作中英文竖屏版，制作前阅读本文件；只做竖屏或额外原理短片时也适用。认可的版式样片见 [画面总览](../assets/examples/vertical-layout-demo/contact-sheet.jpg) 和 [15 秒演示](../assets/examples/vertical-layout-demo/preview.mp4)。样片只作版面参考，不是完整成片；其中的黄绿、珊瑚配色不是固定品牌色。

## 1. 先分清交付类型

- **完整竖屏版**：默认四版中的竖屏交付，一条可独立观看的完整视频，和对应语言的横版讲同一个核心机制。尽快进入具体问题，用场景或例子解释并交代边界与结尾；可单独写更精炼的稿件，不必保留横版所有铺垫，也不按 30–60 秒硬截。用户要求一分钟以内的缩减版时，按下面的短片规则重写，不硬塞完整横版稿。同稿时可复用该语言的声音、字幕时间线和事实，画面仍按 9:16 重新编排。
- **竖屏原理短片／缩减版**：通常 30–60 秒，尽量不超过一分钟，只讲清一个主问题。首句用具体处境、异常现象或直接问题让观众进入；可先给原理，但不强制先报术语。保留必要的共鸣细节和因果过程，最后给完整答案；生活题可给针对阻碍的小动作，历史科学题可交代结论与边界。它可以为竖屏单独写稿，不等于横版的随意截取。
- **默认双语四版**：每期按中文横版、中文竖版、英文横版、英文竖版规划四种成片，无需用户逐期提出双语需求。仅在用户明确缩小本次范围时调整。中英文竖屏共用下面的版式原则；英语内容按英语观众重新组织，不逐句硬译。额外原理短片或切片不计入默认四版。

完整竖屏和原理短片都用原生 9:16 画面。`scripts/clip.sh` 会把横版视频放进竖版底图中，属于旧式包装；除非用户明确要这种样式，不用它代替本版式。

## 2. 版面规则

画布默认 1080×1920、24 fps。按第九期的阅读顺序组织画面：紧凑品牌/主题栏 → 一句对白或情境提示 → 占据画面主体的剧情场景或原理图 → 独立字幕区 → 轻量进度和收尾。它们是稳定的功能分区，不是每镜都要画成五条色块。

- 主场景和解释图在竖屏里占主体面积。角色、手上物件、图表都按手机尺寸重新取景；不能把横版缩成一条小窗口塞在底部，也不能让说明字盖住主要动作。
- 开场可用完整场景和短对白气泡；讲原理时可切换为占满画面的因果图、数据图或机制卡，再回到人物完成故事。解释页可以缩小角色作为观察者，但角色不能挤成一条装饰边。
- 顶部只放必要的账号识别、主题或当前段落；对白气泡、章节标题和画面字幕彼此错开。字幕使用独立且稳定的区域，通常一到两行；按实际语速和语言调字号、断行，不把字幕贴在平台按钮覆盖区。
- 预留平台界面安全区：顶部、底部与右侧不放关键字、角色表情或数据结论。底部只保留简洁进度/品牌收尾，不在那里叠加会挡住主体视频的文字面板。
- 让构图稳定、视线和动作有方向。推拉或摇移只在表达内容时使用；避免整屏持续晃动。人物、对白、字幕、图表同时出现时，先删减次要元素，不互相压住。

## 3. 中英文和内容节奏

中文与英文可以有不同的对白长度、停顿和字幕断行，但镜头层级、主场景位置、解释页位置、字幕区和底部安全区保持一致。中文以意思完整、口语自然为先；英文每行更短，按词组和语义断行，禁止照搬中文自动换行或为了容纳长句缩成难读的小字。逐镜用真实字体渲染后检查，不只看脚本字符数。

竖屏开头约 3 秒让观众认出问题或处境，不先铺一大段人物背景。随后用一个可视化场景或例子走完“发生了什么 → 为什么 → 结果/边界是什么”，再收在具体答案上。共鸣放在具体动作和心里犹豫里，例如想开口又咽回去；不能把所有情绪细节删成一句结论，也不用反复附和拖时长。人物冲突服务于解释，不为竖屏额外加长前奏。

文案仍按 `content.md` 的主讲和推敲规则：同一主讲可以连续说几句，辅助角色只在有作用时开口。一分钟缩减版先删重复接话和旁支知识，保留观众理解所必需的中间原因；超时先缩小问题，不靠继续加速语音或砍掉答案过关。以真实配音计入停顿、转场和片尾后核对总时长，文案自查不能代替发布后的 3 秒留存数据。

## 4. 按主题选颜色

版面结构可以稳定，背景色不能固定。每期根据主题、情绪、地点和机制选一组 3–5 色，明确主背景、对比区域、强调色和中性色；在关键段落复用这组颜色，在场景或情绪改变时再调整。黄色、玫红、青绿、蓝、橙等都只是可选颜色，不指定任何一组为固定背景。

选色时先判断本期整体情绪和场景：疏离、犹豫可尝试冷色底并用少量暖色标记动作；争执、压力可用冷暖对照；松动、恢复可把青绿或其他清爽色作为过渡。它们只是方向提示，不是固定映射，也不要求每期使用相同色相。

主角继续以黑白灰为主体，老白的克莱因蓝围巾保留作角色识别；围巾不限制画面里其他蓝色或鲜艳颜色。高饱和色优先给场景、道具、图表和少量重点，避免所有文字和小物件都争抢注意力。检查字幕与背景的明暗对比；需要时加实色字幕底、描边或换到空白区，不能只靠颜色差异区分信息。

## 5. 制作与验收

同一语言的横版和竖版若使用同一脚本，就复用该语言已核验的配音、混音、事件时间和字幕时码；只重新绘制竖屏镜头，不改横版工程的构图或成片。英文稿或竖屏专用稿有改写时，重新生成对应音频、时间线、字幕和事实核对，不能沿用中文时码。

当前 episode 模板的 `build.sh` 默认只生成横版。制作完整竖屏时，在本期工程增加 `portrait.js` 原生竖屏绘制逻辑，并让 `main.js` 的 `mode=portrait` 调用它；竖屏绘制读取本期相同的角色、台词、时间线和字幕数据。确认这一模式已实现后，用随包 Lemo 渲染器输出：

```sh
node "$LIB/core/render/video.mjs" "$PROJECT" --fps 24 --workers 4 --q 'mode=portrait' --size 1080x1920 --out "$PROJECT/out/portrait/video.mp4"
```

将竖屏画面与对应语言的混音合成，再沿用 episode `build.sh` 的最终转码设置，输出 H.264/AAC、yuv420p、BT.709、faststart 文件。不要把“命令运行成功”当作 portrait 分支已接通的证据；先在短时长样片上检查实际画面。

最终逐项检查：

- 开头、中段机制图、结尾各看实际渲染帧；另外检查转场、长字幕和人物持物的连续帧。
- 在手机比例预览里确认人物脸、关键物件、字幕、解释文字都完整，不被裁边或平台安全区遮挡；检查中英文真实断行。
- 从头到尾播放，核对声音、口型、字幕时码、因果图与口播一致。完整竖屏同稿时核对时长和混音与对应横版匹配；不同稿件按各自时间线核验。
- 用 ffprobe 确认 1080×1920、24 fps、H.264/AAC、yuv420p；完整解码，检查黑帧、响度、真峰值与开头/结尾是否完整。横版和竖版各自验证，不能用一版的 QA 报告替另一版背书。
- 图表上的数字必须来自 `FACTS.md` 核实过的资料；情景模拟或理论示意清楚标成示意，不做成像真实抓取的数据屏。
