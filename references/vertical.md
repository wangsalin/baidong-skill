# 白洞竖屏版式与制作

每期默认制作中英文竖屏版，制作前阅读本文件；只做竖屏或额外原理短片时也适用。认可的版式样片见 [画面总览](../assets/examples/vertical-layout-demo/contact-sheet.jpg) 和 [15 秒演示](../assets/examples/vertical-layout-demo/preview.mp4)。样片只作版面参考，不是完整成片；其中的黄绿、珊瑚配色不是固定品牌色。

## 1. 先分清交付类型

- **默认竖屏缩减版**：默认四版中的竖屏交付，通常 30–60 秒，尽量不超过一分钟。从本期商业经济问题中选择能独立讲清的子问题，保留必要事实、解释、答案与条件。开头约 3 秒进入问题，不铺人物背景；不随意截横版，也不把原因全部删成一句结论。以真实配音加停顿、转场和片尾核对时长，超时先缩小问题，不靠额外加速塞稿。
- **长竖屏版**：仅在用户本次明确要求时制作；按内容需要展开并单独标注时长。无论长短都需能独立看懂、原生编排；同语言同稿才可复用已核验的音轨与时码。
- **默认双语四版**：每期按中文横版、中文竖版、英文横版、英文竖版规划四种成片，无需用户逐期提出双语需求。仅在用户明确缩小本次范围时调整。中英文竖屏共用下面的版式原则；英语内容按英语观众重新组织，不逐句硬译。额外原理短片或切片不计入默认四版。

所有竖屏交付都用原生 9:16 画面。`scripts/clip.sh` 会把横版视频放进竖版底图中，属于旧式包装；除非用户明确要这种样式，不用它代替本版式。

## 2. 版面规则

画布默认 1080×1920、24 fps。沿用已确认的阅读分区：紧凑品牌/主题栏 → 问题或当前解释提示 → 占据主体的主讲、图表或资料 → 独立字幕区 → 轻量进度和收尾。它们是稳定的功能分区，不是每镜都要画成五条色块；旧演示中的生活剧情不延续为新期要求。

- 主讲、图表和资料在竖屏里占主体面积，按手机尺寸重新取景；不能把横版缩成一条小窗口塞在底部，也不能让说明字盖住关键数据。
- 开场直接呈现问题或案例对象。解释时用资金流、账目、因果图、数据图或资料原页；资料占主体时，发声主讲仍以清晰可见的画中画出镜，由本人音频驱动口型并通过真实出镜检查，不能用静态头像替代。
- 顶部只放必要的账号识别、主题或当前段落；章节标题、资料说明和字幕彼此错开。字幕全部单行，按语义分屏；按实际语速和语言调字号与切屏，不把字幕贴在平台按钮覆盖区，也不缩成难读的小字。
- 预留平台界面安全区：顶部、底部与右侧不放关键字、角色表情或数据结论。底部只保留简洁进度/品牌收尾，不在那里叠加会挡住主体视频的文字面板。
- 让构图稳定、视线和动作有方向。推拉或摇移只在表达内容时使用；避免整屏持续晃动。人物、对白、字幕、图表同时出现时，先删减次要元素，不互相压住。

## 3. 中英文和内容节奏

中文与英文可以有不同的口播长度、停顿和字幕分屏，但镜头层级、主讲位置、解释页位置、字幕区和底部安全区保持一致。中文以意思完整、口语自然为先；英文按词组和语义拆成单行分屏，禁止照搬中文自动换行或为了容纳长句缩成难读的小字。逐镜用真实字体渲染后检查，不只看脚本字符数。

竖屏开头约 3 秒让观众知道问题或看完收获。随后直接讲清“事实是什么 → 为什么 → 能得出什么结论”，有必要时给一个简短例子或演算。去掉生活戏、人物冲突、重复例子与互动铺垫，不强制情绪共鸣或结尾小动作。

文案按 `content.md` 的主讲和推敲规则，连续讲清问题，不安排搭档接话。一分钟缩减版先删重复内容和旁支知识，保留观众理解所必需的中间原因；超时先缩小问题，不靠继续加速语音或砍掉答案过关。以真实配音计入停顿、转场和片尾后核对总时长，文案自查不能代替发布后的 3 秒留存数据。

## 4. 按主题选颜色

版面结构可以稳定，背景色不能固定。每期根据主题、情绪、地点和机制选一组 3–5 色，明确主背景、对比区域、强调色和中性色；在关键段落复用这组颜色，在场景或情绪改变时再调整。黄色、玫红、青绿、蓝、橙等都只是可选颜色，不指定任何一组为固定背景。

颜色帮助区分对象、资金流、数据系列和信息层级，同一对象跨镜保持可辨认的对应关系。冷暖对比可标重点，增减或类别同时配文字、形状或符号，不只靠颜色传递含义；不按争执或人物情绪强行配置场景。

八位人物继续保留各自确认稿中的黑白灰主体、服装和识别配饰，不统一替换为老白造型；配饰不限制画面里其他蓝色或鲜艳颜色。高饱和色优先给场景、道具、图表和少量重点，避免所有文字和小物件都争抢注意力。检查字幕与背景的明暗对比；需要时加实色字幕底、描边或换到空白区，不能只靠颜色差异区分信息。

## 5. 制作与验收

同一语言的横版和竖版若使用同一脚本，就复用该语言已核验的配音、混音、事件时间和字幕时码；只重新绘制竖屏镜头，不改横版工程的构图或成片。英文稿或竖屏专用稿有改写时，重新生成对应音频、时间线、字幕和事实核对，不能沿用中文时码。

episode 模板现已包含 `portrait.js` 原生绘制分支。新建时传 `--aspect portrait`，在本期 portrait.js 改写场景，运行同一个 build.sh；它自动选择 mode=portrait、1080×1920，并共用固定人物、字幕和品牌包装。不能重写 main.js 自造竖版外壳。

```sh
sh "$BAIDONG_SKILL_ROOT/scripts/new_episode.sh" local example-zh-portrait "$OUTPUT_ROOT" --language zh --aspect portrait
sh "$OUTPUT_ROOT/example-zh-portrait/build.sh"
```

测试样片默认有明确水印。只有对应声音具备真实认可记录才能转 final；运行成功仍不代替以下效果检查。

最终逐项检查：

- 开头、中段机制图、结尾各看实际渲染帧；另外检查转场、长字幕和人物持物的连续帧。
- 在手机比例预览里确认人物脸、关键物件、字幕、解释文字都完整，不被裁边或平台安全区遮挡；检查中英文真实断行。
- 从头到尾播放，核对声音、口型、字幕时码、因果图与口播一致。完整竖屏同稿时核对时长和混音与对应横版匹配；不同稿件按各自时间线核验。
- 用 ffprobe 确认 1080×1920、24 fps、H.264/AAC、yuv420p；完整解码，检查黑帧、响度、真峰值与开头/结尾是否完整。横版和竖版各自验证，不能用一版的 QA 报告替另一版背书。
- 图表上的真实数字必须来自 `FACTS.md` 核实过的资料与可复算底稿；假设账本、演算或理论图清楚标成示意，不做成像真实抓取的数据屏。
