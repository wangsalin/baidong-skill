## 1. 选题与内容角度

选题按 `account.md` 的商业案例、生活经济、工作与收入三条主线。先记录来源和可核对的需求信号：评论原话、用户指定、现实问题或对标内容等；注明具体出处，没有就标记“需求未验证”。不抓取或模拟登录平台，不把主观打分当作流量证明。

在本期 `TREATMENT.md` 或已有策划中说清：

- **主问题与受众**：谁值得听，究竟想弄懂什么？问题要具体，收获要足以支撑一条内容，避免为微小细节反复铺垫。
- **看完收获**：一个有依据的答案、对生意或规则的新理解，或一组能说明适用条件的判断方法；不强制行动建议。
- **解释路径**：要回答主问题，必须先弄清哪些事实和关系？可以有多个必要因素，不限于一个机制。
- **证据路径**：有哪些原始文件、数据、研究或可核实案例，缺什么？找不到依据时收窄问题，不靠虚构故事填空。
- **画面用途**：资金流、价格拆分、时间变化、对照、报告原页等，具体帮助观众看懂哪一步。

工作台的旧评分保持兼容：`共鸣` 看观众是否关心，`冲突` 看问题或解释是否存在值得追问的落差，`和我有关` 看收获与目标受众的联系，均为1–5分。12/15分仅用于候选排序。旧关系桶不再决定立项与轮换，字段写法见 `distribution.md`。

### 比较三个解释角度

围绕同一题比较3个有实质差别的切口，各写问题、关键判断、拟用证据、收获与限制。可以从定价与成本、各方分账、供需变化、模式对比、时间变化等切入，不只改标题，也不要求每期制造反转。

例如“9.9元咖啡”可分别研究优惠成本由谁承担、品牌与门店分别赚什么、低价怎样影响获客与复购。是否成立须查实际品牌、期间和活动规则；不能先把“低价一定赚钱”写成答案。

## 2. 开头与内容承诺

第一句直接让观众知道今天要弄懂什么或能获得什么，第一帧有可读信息，不放独立开场片头、寒暄或冗长背景。约3秒是进入问题的编辑目标，不是塞完答案或研究背景的硬时限。

| 类型 | 适合怎样的问题 | 题目示意，仍须研究与正文兑现 |
|---|---|---|
| 直接提问 | 对一个对象有明确疑问 | “这杯9.9元的咖啡，谁在承担优惠？” |
| 有依据的落差 | 表面结果与实际账目不同 | “营业额涨了，利润为什么反而少了？” |
| 明确收获 | 一组方法能服务同一问题 | “看懂一家店赚不赚钱，先分清这三笔账。” |
| 证据切入 | 一张表或一个事实能引出问题 | 先展示真实账目或报告中的关键差异，再提出要解释的问题 |

为选定角度比较3种开头，按问题清晰度、好奇心、可信度、受众与后文兑现选择；不只挑最短或最夸张的一句。标题、封面和开头指向同一承诺。不能先制造并不存在的常识、行业内幕或科学争议，再以反转包装；也不先报答案却用后半条重复它。

## 3. 讲解结构与时长

按观众此刻要弄懂的事组织内容，不按人物经历排剧情。可用下面的讲解方式，按题目组合，不规定段数、每段秒数或知识点数量：

| 讲法 | 怎样展开 |
|---|---|
| 商业模式拆解 | 谁付钱、买什么 → 收入与成本 → 谁赚到哪笔钱 → 成立条件与限制 |
| 数据与趋势 | 先给可比事实 → 解释变化 → 检查其他因素 → 回答能推出什么 |
| 案例或方案对照 | 明确比较问题 → 在一致口径下比较 → 说明差异原因与适用条件 |
| 方法分点 | 先说这组方法解决什么 → 每点讲清依据、用途和简短例子 → 回答原问题 |

横版把问题、依据和必要解释展开，不按固定4分钟或固定字数凑稿。竖版仍执行通常30–60秒的缩减交付规则：选一个能独立讲完的子问题，保留关键因果、答案与必要边界；长竖屏按用户本次要求执行，见 `vertical.md`。不额外加速固定角色配音来塞稿。以真实音频、停顿和品牌收尾核时长。

工作台 `seg.s1–s6` 是旧存储结构，按 `distribution.md` 映射实际讲稿；不反过来要求六段剧情。`story.js` / `scenes.js` 是技术文件名，也不意味着需要故事演绎。

### 整篇为什么值得继续听

- **及时增加理解**：一段应带来新事实、解释、比较或判断依据。观众已经知道的结论不换三种说法重讲，不把多个琐碎例子当作多个信息点。
- **前后有具体关系**：一句解释应回答刚才的疑问，或为下一步提供必要依据。报完数字要说它意味着什么，不靠“真正可怕的是”“更惊人的来了”维持期待。
- **边推进边回答**：已经能解释的部分及时说清，再引出自然的新问题；不把本来几句话就能说清的答案藏到最后。
- **按需要给例子**：例子应让一条关系更容易理解，主讲几句话说明即可。重复证明同一结论的菜单、买菜、洗碗等细节应合并，不演完整生活过程。
- **回答后及时结束**：收在开头的问题与证据支持的结论上；有适用条件就交代，不固定加感悟、安慰、生活建议和评论提问。

## 4. 主讲、案例和解释

### 主讲连续说清楚

从 `characters.md` 的A1–D2中按题目选主讲，保持姓名、性格、固定声音和后处理。谁说话谁出镜，用本人音频驱动口型。主讲自己提出必要问题并接着解释，去掉剧情演绎、争执、捧哏和搭档轮流拆短句。确需多人分节时，各自连续负责有实质内容的部分。

人物个性体现在语气、措辞、节奏和简洁判断里，不以方言堆砌、口头禅或无关笑话占篇幅。自然口语可以有不同长短；先写完整思路，再按换气和字幕语义分句。配音分句不等于换人或断开因果。

### 解释讲到听者能接上下一步

- **说清关系**：成本、利润、供需、竞争等名词不是答案。讲明谁付了什么、什么条件发生变化、怎样影响结果；观众不需要先学完整学科。
- **定义放在需要处**：首次用口语解释专业名词，相关缩写说明含义。例如先分清营收、毛利、净利和现金流，再比较“赚了多少钱”；不在开头堆概念目录。
- **案例与类比服务解释**：真实案例按第6节研究；类比、假设账本与演算标明身份和适用范围，不把类比当作证据，不编造采访、亲历或成功结果。
- **比较先核口径**：同一价格可能含补贴、税或服务费，企业报表与加盟店账目可能属于不同主体。条件不一致时先说明，不能用模糊的“商家赚了”一笔带过。
- **观点跟着证据走**：区分事实、计算与解释，不把相关关系直接写成因果，不把一种做法说成所有行业都适用。
- **画面支持关键一步**：钱流向谁、成本怎样拆、数据怎样变，分别用资金流、账目、图表或资料原页展示；绘制与资料规则见 `visual.md`。
- **保持可听性**：配音数字用汉字写在 `say`，字幕 `text` 可用阿拉伯数字；听辨含混的词换自然说法，不降低ASR校验掩盖问题。

## 5. 文案推敲与留存复核

通读完整口播，先找最可能让人失去兴趣的具体段落：背景过长、同义反复、例子过细、报数不解释、抽象概念连发或答案不足。修改后重读前后文，将实质问题、句子与删改理由写进现有 `TREATMENT.md`；不增加逐句评分表和固定修改轮数。

1. **沿观众的疑问读**：每次因果、比较和判断能否从已交代的事实接上？不借助分镜说明也能听懂核心原因，必要术语有解释。
2. **沿证据读**：关键数据、企业事实和研究能否找到出处与计算？主体、期间、单位和比较条件是否一致？推测是否说成定论？
3. **从结尾倒查开头**：用普通话直接回答主问题，正文逐步给出依据。若只能得到一句常识或金句，回到选题或解释本身补价值，不再添加剧情包装。

交稿前确认以下结果；失败项回到具体段落修改：

- [ ] 开头直接明确问题或收获，标题、封面和正文兑现同一承诺
- [ ] 主题属于当前商业经济主线，有足够信息与解释价值，不只说一个人人已知的结论
- [ ] 主讲连续、口语自然，去掉剧情演绎、无效接话、重复例子与冗长背景
- [ ] 必要追问有答案，数字有含义，因果与比较条件完整
- [ ] 企业事实、数字与研究有出处，假设、类比和推断与事实分开
- [ ] 画面帮助读懂数据或关系，真实资料身份清楚，人物与固定声音一致
- [ ] 结尾回答开头，不硬塞行动建议、情绪升华或互动口号
- [ ] 时长与画幅相称，竖版解释独立完整；配音与单行字幕能自然跟上
- [ ] 若有付费合作，商业关系明确标注，结论和产品表述仍有依据

这是案头编辑，不是观众试听或留存测试。发布后的观察按 `distribution.md` 使用用户实际提供的数据，不声称规则修改已提高流量。

## 6. 事实表

`FACTS.md` 一行一条：台词里的说法 → 出处链接 → 原文摘录（或测量方法）→ 证据与台词的关系。规则：

- 只用打开过的页面，不用搜索摘要。
- 学术结论优先找论文或权威机构页面；新闻只用于事件本身。
- 查不到出处的数字或研究结论删掉或缩窄到有证据支持的说法；不能用“好几倍”“很多人”掩盖缺少证据。生活类比明确是示例，不伪装成研究结果。
- 有争议的说法交代证据支持到哪一步。区分“已观察到的现象”“主流解释”“仍在估算的细节”；不把有共识的机制和缺少依据的猜想并列成同等可信，也不把模型估计写成现场实测。不能只加“一种解释是”就保留无出处的说法。
- 标明台词属于原研究直接结果、基于研究的解释，还是生活类比；不要让一条研究看起来支持它没有研究过的状态或人群。
- 记录会改变结论的适用条件和争议；必要时缩窄台词，不用讲故事的顺滑度覆盖证据边界。
- 同步写进工作台 `facts` 字段（每条 `{o, claim, url}`）。

### 真实商业案例的研究

允许分析有名称的真实企业、品牌、产品和经营者的相关经营行为。围绕本期主问题研究，不写成公司履历、创始人传奇或宣传介绍；也不从成功结果倒推“只要照做就能成功”。

- **先确认对象和时间**：研究的是集团、品牌、直营门店、加盟商、平台还是供应商？事件和数据属于什么期间、市场与业务范围？品牌利润不能自动当作加盟店利润。
- **优先原始资料**：年报、招股书、财报附注、官方产品或活动规则、统计机构资料、原研究等。企业自述、管理层目标和预测标明身份；争议或重大经营判断核对独立材料，缺少佐证时保留限制。
- **按问题拆账**：查清客户付给谁、换取什么、主要收入与成本、补贴由谁承担、利润或现金怎样留下来。需要数据支撑的答案按下节提取与复算；公开资料没有披露门店利润时，不能用集团利润率冒充。
- **解释成立条件**：按问题检查规模、供应链、渠道、获客、复购、竞争或时期变化。只保留影响答案的因素，说明其他解释、失败条件和不能推广之处，不强制逐项凑齐。
- **留可追溯底稿**：在既有 `TREATMENT.md` 记录研究问题、解释路径和未决项，在 `FACTS.md` 对应关键事实，在 `DATA.md` 或已有分析底稿保存口径、原表与计算。素材沿用 `CREDITS`，不另建重复文档。

案例分析与广告合作按 `account.md` 区分。品牌提供材料也要核验，未实测不写成亲测；商业合作不能替代独立的事实与计算。

### 数据类选题：必须做真实数据分析

涉及规模、变化、成本、收入、收益、占比、排名等数据论证时，在事实核验基础上完成以下工作；单个关键数字也要核口径，不按数据条数凑工作量。

- **先定要回答的问题，再取数据**：优先打开统计机构原文、企业原始披露、原研究或用户授权的数据文件。把实际数值、单位、时间、对象、样本与定义记入本期 `DATA.md` 或既有数据分析底稿，保留原表页码/表号或获取方法；多条数据可另存 CSV/JSON，不能只留搜索摘要或二手转述。
- **分析而不只罗列**：按观众疑问选择可比的趋势、差异、结构或经营拆解，复算关键比例、增减、公式和单位换算，保留计算过程。交代样本偏差、缺失值和不可比项怎样影响结论；不同期间、群体或统计定义不得无说明拼接，相关变化不能直接写成因果。
- **让结论能被追溯**：在底稿中对应写明“数据是什么 → 怎样分析 → 支持什么 → 不能推出什么”，台词引用关联 `FACTS.md`。标题、封面和口播承诺不能超出证据；缺少比较数据时，不使用“最快”“最容易”等排名结论。
- **真实数据与演算分开**：教学假设、模型估计和虚构人物账本分别标明，不装成实测或行业均值。假设演算可以解释机制，但不能代替本题所需的真实数据分析；拿不到可靠数据时如实说明并收窄论证，不硬造数据。
- **数据变成解释画面**：正文用口语说明数字回答哪个问题，再用对应图表或原表局部帮助理解。图上保留来源、期间、单位、样本及必要脚注，核对坐标起点、分母和百分比口径；不靠裁掉脚注、截断坐标或选择性对比制造冲突。
- **同步规划真实 B-roll**：主动查找与关键说法对应的真实图片、视频、公开报告原页或实拍资料，优先选能增加证据或帮助理解的内容。是否可进入成片、怎样标注和保持人物出镜，按 `visual.md` 的真实资料规则处理；没有合适素材时说明缺项，不为凑画面冒用别的事件。

## 7. 标题、封面文案、评论区

封面提炼本期对象、问题、价格、差异或账目关系，用观众听得懂的短标题。必须有正文依据，不捏造企业恶意或“行业内幕”；不能以“营收”冒充“利润”、用假设数字包装实际业绩。画法、四比例独立构图与手机检查见 `covers.md`。

| 平台 | 写法 |
|---|---|
| B站 / YouTube | 明确问题、对象和内容范围，可按需要补关键解释方向 |
| 抖音 / 快手 | 直接、口语化，尽早说清问题或看完收获 |
| 小红书 | 具体问题或判断方法，不硬套第一人称焦虑与“终于想通了” |
| 视频号 | 清楚说明这件事与消费、收入或生意的联系，不强套家庭转发口吻 |

实际标题长度遵循平台限制；短标题不牺牲主体、时间和条件。简介写本期问题、主要内容、必要来源或边界，有自然讨论点时再附问题。B站与YouTube提供对应语言和真实时间线的章节。

标签选择 `#白洞`、案例对象、主题与经济商业领域词，避免无关热点。置顶评论可补资料、说明口径或问一个具体问题，不编造用户反馈。小红书6张卡按“问题 → 关键事实 → 解释/对照 → 答案与条件”分配，不强制最后给生活动作。平台文案、简介和卡片有付费合作时保持明确标注，不能在分发时抹去商业关系。
